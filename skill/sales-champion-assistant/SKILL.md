# 销冠助手

GitHub: [guiltyluce/sales-champion-assistant](https://github.com/guiltyluce/sales-champion-assistant)

用于把一个企业名称整理成可执行的客户调研与建联策略。报告需要覆盖企业信息星标评级、招聘薪资观察、企业基本信息、权力地图、资本与政府关系、产业链、战略焦虑、资源匹配路径和高管沟通建议。

曾用技能名：`company-intel-report`。新仓库和新 Skill 使用 `sales-champion-assistant`。

# 触发场景

用户出现以下意图时使用：

- 做客户调研、企业调研、客户画像、企业尽调。
- 为销售、BD、招商、生态合作准备拜访材料。
- 想了解某家公司，并要求给出建联抓手、破冰方式或沟通建议。
- 需要把公开信息整理成报告、摘要或作战手册。

典型表达：

- `查一下 XXX 公司`
- `帮我做一份 XXX 的客户画像`
- `给我一份 XXX 公司的 BD 拜访策略`
- `这个客户怎么破冰`
- `整理一下 XXX 的企业情报和建联路径`

# 输入

- `company_name`：必填，企业名称。
- `benchmark_date`：可选，默认当天。
- `resource_catalog_json`：可选，建议注入团队资源池。
- `industry_focus`：可选，指定关注行业或业务方向。

# 执行流程

1. 检索公开信息，优先级如下：
   - 官方网站、官方公众号、官方新闻稿。
   - 上市公司公告、年报、招股书。
   - 工商和企业信用信息。
   - 招聘 JD 与薪资区间。
   - 政府补助、工信/国资/园区公示。
   - 行业媒体采访与活动发言。
2. 抽取结构化情报：
   - 使用 `references/prompts/company_intel_prompts_zh.md` 的 Researcher 阶段提示词。
   - 输出 JSON 必须遵循提示词中的字段要求，字段缺失时写明信息缺口。
   - `enterprise_info` 必须包含综合评级、GTM 客群 Fact Check、敏感性扫描、严重性检查、五维星级评估、招聘薪资分析。
3. 做质量检查：
   - 缺失信息写“未公开”。
   - 推断必须标注“推测（依据：...）”。
   - 星级评估以三颗星为满分。
   - 严重性检查触发 `severe` 时，综合评级锁定 `★☆☆（高危）`。
   - 必查公开在招岗位和薪资；未检索到时写 `未检索到公开在招岗位`，并列出检索平台。
   - 完整报告的 `evidence` 至少 8 条，其中至少 2 条与企业信息评估或招聘薪资相关。
   - `resource_matching` 至少 3 条，并绑定 `resource_catalog_json`。
4. 生成报告：
   - 使用同一提示词文件中的 Writer 阶段提示词。
   - 输出中文 Markdown。
5. 返回结果：
   - 聊天摘要模式：先返回建联导向摘要，包含评级、招聘观察、建联抓手和信息缺口。
   - 完整报告模式：生成 Markdown 报告和结构化 JSON。

# 输出格式

报告标题建议：

`{公司名} - 企业调研与建联策略报告 ({年份}版)`

固定章节：

- 企业信息与星标评级
- 一、权力地图与人物画像
- 二、资本背景与政府关系
- 三、上下游产业链
- 四、社会足迹与战略焦虑
- 五、资源匹配建联策略
- 六、高管沟通方式建议
- 报告说明

高管沟通建议必须包含：

- 性格与沟通偏好
- 近期核心焦虑
- 多聊 / 少聊 / 绝对不要聊

企业信息与星标评级必须包含：

- 综合评级：`★★★/★★☆/★☆☆（标签）`
- GTM 客群 Fact Check：员工数、归类、来源、置信度
- 敏感性扫描与严重性检查
- 五维星级评估：行业增长、行业地位、区域地位、财务和资本、管理层画像
- 招聘信息与薪资水平分析：在招岗位、薪资区间、岗位结构、成长性/行业地位信号

# 注意事项

- 只使用公开可核验信息。
- 不输出违法、侵权、诽谤内容。
- 不把来源不明的传言写成事实。
- 不涉及未披露内幕信息。
- 页面超时、搜索不可用、招聘平台打不开时，把问题写入信息缺口。
