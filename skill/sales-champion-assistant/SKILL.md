# 销冠助手

## 这是什么

拜访一个客户之前，你需要的不是百科词条，是**作战手册** 🎯
丢一个企业名称进来，产出：星标评级、权力地图、战略焦虑、资源匹配路径、
高管沟通建议（多聊什么 / 少聊什么 / 绝对不要聊什么）。

**什么时候用我：**

- 「查一下 XX 公司」「帮我做一份 XX 的客户画像」
- 「这个客户怎么破冰」「给我一份 BD 拜访策略」
- 销售 / BD / 招商 / 生态合作的拜访前功课

**产出长什么样：**

```text
企业信息与星标评级（★★★ 满分，含严重性检查一票否决）
  ├─ 一、权力地图与人物画像
  ├─ 二、资本背景与政府关系
  ├─ 三、上下游产业链
  ├─ 四、社会足迹与战略焦虑
  ├─ 五、资源匹配建联策略（绑定你的资源池）
  └─ 六、高管沟通方式建议
```

**纪律明牌**：只用公开可核验信息；缺失写"未公开"，推断必须标注依据；
不碰内幕信息，不把传言写成事实——评级体系经真实客户案例回测校准。

GitHub: [wetlink/sales-champion-assistant](https://github.com/wetlink/sales-champion-assistant)

用于把一个企业名称整理成可执行的客户调研与建联策略。报告覆盖：综合评级（行业双维主导判定表）、GTM 客群 Fact Check、五维星级评估、深度背景调查（含数字化实践与矛盾核查）、招聘薪资观察、权力地图、资本与政府关系、产业链、战略焦虑、资源匹配路径和高管沟通建议。

曾用技能名：`company-intel-report`。新仓库和新 Skill 使用 `sales-champion-assistant`。

# 触发场景

用户出现以下意图时使用：

- 做客户调研、企业调研、客户画像、企业尽调。
- 为销售、BD、招商、生态合作准备拜访材料。
- 想了解某家公司，并要求给出建联抓手、破冰方式或沟通建议。
- 需要把公开信息整理成报告、摘要或作战手册。

典型表达：

- `查一下 XXX 公司`
- `帮我做一份 XXX 的客户画像`
- `给我一份 XXX 公司的 BD 拜访策略`
- `这个客户怎么破冰`
- `整理一下 XXX 的企业情报和建联路径`

# 输入

- `company_name`：必填，企业名称。
- `benchmark_date`：可选，默认当天。
- `resource_catalog_json`：可选，建议注入团队资源池。
- `industry_focus`：可选，指定关注行业或业务方向。

# 执行流程

1. 检索公开信息：
   - 按 `references/prompts/company_intel_prompts_zh.md` 中"检索可靠性 Playbook"执行：官方层 → 工商信用层（天眼查/爱企查/企查查/信用公示）→ 招聘层（BOSS 直聘/猎聘/智联/职友集等）→ 媒体/百科层。
   - 使用其中的检索词模式库；同一 URL 或失败工具最多重试 1 次，失败即降级切换来源，不空转；每家企业检索预算建议 12-15 次。
2. 抽取结构化情报：
   - 使用同一提示词文件的 Researcher 阶段提示词。
   - 输出 JSON 遵循 `references/schema/company_intel_report.schema.json`，字段缺失时写明信息缺口。
   - `enterprise_info` 必须包含：综合评级（含 rating_logic 判定表命中行）、GTM 客群 Fact Check（含来源平台与是否第三方估算）、敏感性扫描、严重性检查、五维星级评估、深度背景调查（background_check，含数字化实践与矛盾核查）、招聘薪资分析。
3. 做质量检查：
   - 缺失信息写"未公开"；推断必须标注"推测（依据：...）"；不得编造。
   - 综合评级按"行业双维主导判定表"执行：严重性检查 `severe` 熔断最优先锁定 `★☆☆（高危）`；否则由行业增长+行业地位双维定基准档，区域/财务/管理层按补充规则调节；标签只允许"高潜领军者/中坚力量/稳健/高危"四种。
   - 行业增长维度必须给政策锚点（"十五五"规划等具体条目）和行业增速 vs GDP 数字对比；缺数字最多 ★★☆。
   - 管理层画像必须输出先进因子（F1-F7）命中清单、"命中 N 个"计数和类型标签。
   - 数字化实践为必查项（SaaS/ERP 使用、数字化荣誉）。
   - 第三方估算数据必须标注 `⚠️第三方估算（平台名）`。
   - 来源矛盾（官网沿革 vs 工商注册等）必须显式指出并给解释假设。
   - 必查公开在招岗位和薪资；未检索到时写 `未检索到公开在招岗位`，并列出检索平台。
   - 完整报告的 `evidence` 至少 8 条，其中至少 2 条与企业信息评估或招聘薪资相关。
   - `resource_matching` 至少 3 条，并绑定 `resource_catalog_json`。
4. 生成报告：
   - 使用同一提示词文件中的 Writer 阶段提示词。
   - 输出中文 Markdown。
5. 返回结果：
   - 聊天摘要模式：先返回建联导向摘要，包含综合评级（含判定依据）、GTM 客群、五维星级、数字化实践结论、招聘观察、3 条建联抓手和信息缺口。
   - 完整报告模式：生成 Markdown 报告和结构化 JSON。

# 输出格式

报告标题：

`{公司名} - 企业调研与建联策略报告 ({年份}版)`

固定章节：

- 综合评级：`★★★/★★☆/★☆☆（标签）` + 一句话判定依据（判定表命中行）
- GTM 客群 (Fact Check)：`[来源：⚠️第三方估算（平台名）或官方披露] 员工总数 X 人（归类）`
- 【PART 1: 星标评级评估】：1.敏感性扫描 2.严重性检查 3.星级评估（行业增长、行业地位、区域地位、财务和资本、管理层画像，每维带具体论据）
- 【PART 2: 深度背景调查】：业务概览 / 发展历程 / 财务与股东 / 创始人与团队 / 数字化实践 / 招聘与薪资信号
- 【PART 3: 权力地图与人物画像】
- 【PART 4: 资本背景与政府关系】
- 【PART 5: 上下游产业链】
- 【PART 6: 社会足迹与战略焦虑】
- 【PART 7: 资源匹配建联策略】（按优先级：匹配逻辑 + 执行路径）
- 【PART 8: 高管沟通方式建议】（每人：性格与沟通偏好、近期核心焦虑、多聊 / 少聊 / 绝对不要聊）
- 综合说明：销售视角结论（客户价值定位与切入点）、矛盾核查汇总、信息缺口、免责说明

# 交付方式

- **飞书智能体环境（默认出云文档）**：当运行环境具备飞书文档写入能力（如 feishu-doc、lark-doc 类技能或同等工具）时，完整报告**默认生成飞书云文档版本**，并把文档链接连同聊天摘要一起回复——聊天摘要不能替代云文档，除非用户明确说明不需要文档。文档标题用报告标题；可选将综合评级、星级、建联抓手等结构化字段沉淀到多维表格客户库，便于团队复用。
- 本地 CLI 环境：本地落盘 Markdown 报告 + 结构化 JSON（如 `output/reports/{company_name}-{YYYYMMDD}.md/.json`），聊天入口先给摘要。
- 环境不具备飞书写入能力时静默跳过云文档交付，不视为失败。

# 注意事项

- 只使用公开可核验信息。
- 不输出违法、侵权、诽谤内容。
- 不把来源不明的传言写成事实。
- 不涉及未披露内幕信息。
- 页面超时、搜索不可用、招聘平台打不开时，把问题写入信息缺口并降级，不反复重试同一失败来源。
